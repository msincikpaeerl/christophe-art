# Languages (i18n)

The public site exists in French (`fr`, the default) and English (`en`). The admin stays in French only. The **address is the only source of the language**: no cookie remembers it.

All the code is in `src/i18n/`; the pages are in `src/pages/[lang]/`.

## Rules every public page follows

- It lives under `/fr/...` or `/en/...`. Fixed page paths are translated through the **route table** (`src/i18n/routes.ts`), for example `/fr/galerie` and `/en/gallery`. Content slugs (an artwork, a collection…) are shared by both languages: `/fr/galerie/hex-tree` and `/en/gallery/hex-tree`.
- `/` is the only address that redirects by browser language: `302` to `/fr/` or `/en/` with `Vary: Accept-Language`, French when no supported language is accepted (`src/pages/index.ts`, `negotiate.ts`).
- The page uses `BaseLayout` with `locale` and `route`. The layout then sets `<html lang>`, the canonical URL, the `hreflang` links (`fr`, `en`, `x-default` = French) and the language switch. Canonical and `hreflang` addresses never carry the filters of the address; the switch does, so `/fr/galerie?category=sculpture` leads to `/en/gallery?category=sculpture`.
- An unknown prefix (`/de/`, `/nope`) answers a 404 in French; an unknown page under `/fr/` or `/en/` answers a 404 in that language, with a link to the home page.
- Canonical and `hreflang` addresses are absolute and start with the `SITE_URL` setting (for example `https://christophe.art`). Set it in production: without it, the address the server sees is used, which is wrong behind a reverse proxy.
- Prices, dimensions and dates go through `src/i18n/format.ts` (`1 200 €` in French, `€1,200` in English). Never format them by hand.
- A content field is `{ fr, en }`. When the English text is empty, the French one is shown in its place, marked `lang="fr"` for screen readers: use the `LocalizedText` component, or `pickLocalized` in code.
- No interface text is written in a public component or page: it comes from the dictionaries. A test (`src/i18n/hardcoded-text.test.ts`) fails on text or on `alt`, `title`, `aria-label` or `placeholder` written directly in the markup of `src/components`, `src/layouts` and `src/pages` (the `dev` pages are excluded).

## Add an interface text

1. Add the key to `src/i18n/dictionaries/en.ts` (it defines the shape).
2. Add the same key to `src/i18n/dictionaries/fr.ts`. TypeScript refuses a missing or extra key.
3. Use it with `const t = translator(locale)` then `t('group.key')`. Write the key **in full, as a quoted string** (never built from pieces): a test (`dictionaries.test.ts`) fails when a key is missing in a language, empty, or unused by the code.

## Add a route

1. Add one line to `routes` in `src/i18n/routes.ts`: `team: { fr: 'equipe', en: 'team' }`. Segments use only lowercase letters, digits and dashes (a test checks it, and that no two pages share an address).
2. Link to it with `pathFor('team', locale)`; never write `/fr/...` by hand.
3. The route tests (`routes.test.ts`) and the end-to-end switch tests then cover it; add the page to the `pages` list in `e2e/i18n.spec.ts`.

## Add a page

1. Add its route (above) and its texts (above), including its title.
2. Give it a design: `src/pages/[lang]/[...slug].astro` resolves the address with `resolveRoute` and shows a placeholder for pages without one. Add a branch there for the new page (or move its body into a component the branch uses). Do not create a file per language: the same page serves both.
3. Pass `locale` and `route={{ key, rest }}` to `BaseLayout`, so the switch, canonical and `hreflang` are right. A page outside the route table (development pages) passes `alternates` instead and no canonical is written.
4. Add the navigation entry in `src/site.ts` if it belongs in the header or footer.
5. Add the page to the switch and metadata tests in `e2e/i18n.spec.ts`.

## Tests

| What                                                       | Where                                            |
| ---------------------------------------------------------- | ------------------------------------------------ |
| Route table, language negotiation, formatting, fallback    | `src/i18n/*.test.ts`                             |
| Dictionaries complete and used, no hard-coded text         | `dictionaries.test.ts`, `hardcoded-text.test.ts` |
| Root redirect, switch on every page, 404s, canonical links | `e2e/i18n.spec.ts` (desktop, phone)              |
